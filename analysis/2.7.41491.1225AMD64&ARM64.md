## Scope

Binary-level analysis of the **amd64 and arm64 `GuestAgentPackage.zip`** assets only.
The `.wim`, `.msi`, and `_PDBs.zip` assets were intentionally excluded. The baseline
(2.7.41491.1216) amd64/arm64 `GuestAgentPackage.zip` assets were downloaded for the
release-to-release diff.

- **amd64 package:** 110 PE files (43 managed, 67 native)
- **arm64 package:** 64 PE files (40 managed, 24 native)

## Summary

Every binary in both packages is validly **Microsoft-signed** (leaf `CN=Microsoft
Corporation`), with a **SHA-256** file digest and an **RFC-3161 timestamp**; no
unsigned or broken-signature binaries were found. Two findings drive risk:

1. **Rust supportability (High).** The native Rust modules `rust_common.dll` and
   `rust_utils.dll` are built with Microsoft **rustc 1.92.0** and **1.84.1**
   respectively (both **≥ 1.78**) and import **Windows 8+/Server 2012+ only** APIs
   (`WaitOnAddress` via `api-ms-win-core-synch-l1-2-0.dll`, and
   `GetSystemTimePreciseAsFileTime`). They therefore cannot load on the agent's
   oldest declared OS, **Windows 7 SP2 / Windows Server 2008 SP2**. This is
   **pre-existing** — the 2.7.41491.1216 baseline ships the same rustc versions and
   the same imports — not a regression in this release.
2. **Signing-certificate change (Medium).** The code-signing chain rotated from
   issuing CA **`Microsoft Code Signing PCA 2011`** (baseline) to **`Microsoft Code
   Signing PCA 2024`** (this release). The leaf subject is unchanged and both chains
   root to `Microsoft Root Certificate Authority 2011` — a benign Microsoft PKI
   rotation, not a compromise.

All managed assemblies still target **.NET Framework 4.0** (CLR `v4.0.30319`; the
sole exception, third-party `srmlib.dll`, is on the legacy CLR `v2.0` and is
unchanged from baseline) — **no .NET drift**. The diff adds exactly one binary,
`WindowsAzureGuestAgentGateKeeper.exe` (matching the "pre-validation gate keeper"
change-list items), removes nothing, and re-signs/rebuilds nearly all binaries
(hash change) consistent with the stated build-image 2019→2022 move plus the
certificate rotation. The net release-specific delta is low; the overall rating is
**High solely because of the carried-over Rust down-level supportability gap**.
